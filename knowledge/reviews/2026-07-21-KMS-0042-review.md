## Implementation summary

**Planned scope**: local embedding model, HNSW vector index, 70/30 blended ranking,
save/delete hooks, top-nav search UI.

**Actual scope**: all planned features shipped. The embedder dim guard from the ADR
was implemented and actually fails loudly — verified by loading a 768-dim model and
watching it refuse to start. Good.

**Deviation**: minor positive — the ranker also exposes the raw semantic and keyword
sub-scores in the API response, which made the eval harness much easier to write.

---

## The big picture

The architecture matches the plan and the ADR. The blend is correct, the index
persists and reloads, and the latency bar is met (p95 = 310ms on the 10k corpus,
see the benchmark artifact). Two real issues before this is fully done, one of them
already has a ticket.

---

## Issues

### 1. Stale index after bulk import — Severity: HIGH (already ticketed: KMS-0043)

Importing a folder of documents does not go through `Document.save()`, so the bulk
path never calls `vector_index.upsert()`. Imported docs are invisible to semantic
search until the next full rebuild. **This blocks ticket sign-off.** Tracked in
`knowledge/bugs/2026-07-19-KMS-0043-stale-search-index.md`.

### 2. Query embedding is recomputed on every keystroke — Severity: MEDIUM

With a 300ms debounce this is usually fine, but a fast typist can queue several
embeds. Cache the last query→vector, or cancel the in-flight embed on a new
keystroke. Not a blocker; open as a follow-up.

### 3. No guard on empty corpus — Severity: LOW

Querying before any document is indexed returns an internal error instead of an
empty result set. One-line fix; fold into the KMS-0043 branch.

## Decision

Approve once KMS-0043 (issue #1) lands. Issues #2 and #3 are follow-ups, not blockers.
